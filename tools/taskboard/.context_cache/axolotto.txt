## 1. ARCHITECTURE OVERVIEW

Axolotto is a Web3 metaverse lottery game with 4 main areas:

  backend/     — FastAPI + SQLModel + PostgreSQL 16  (Docker :8001)
                Auth: Privy JWT (X-Privy-Token header)
                Blockchain: Web3.py -&gt; Anvil/Plasma Testnet
                Key services: bank, game, multiplayer, shop, checkout, incubation

  frontend/    — Next.js 16.2 App Router + React 19 + Tailwind CSS 4 (PM2 :3000)
                Auth: @privy-io/react-auth (social login + self-custodial wallets)
                Web3: Viem 2.47 (NO ethers.js)
                Payments: MoonPay widget for USDC onramp
                Key components: PlayMode, LoteriaBoard, Store, MultiplayerLobby,
                Criadero, Santuario, Inventory, VipModal, CryptoCheckout, MarketP2P

  contracts/   — Solidity + Foundry (Anvil :8545 local / Plasma Testnet chain 9746)
                14 contracts: Frijolito(FRJ), Axoficha(AXF), Webitos(ERC-721),
                Axolotitos(DNA), CartasLoteria, TablasLoteria(escrow),
                Boosters, Consumables, GameController(orchestrator), Frijolito

  tools/       — Self-hosted AI Kanban taskboard (Python stdlib + vanilla JS)
                Path: tools/taskboard/ (SELF-CONTAINED, do not touch other areas)

## 6. CRITICAL RULES (violating these breaks production)

  1. CONCURRENCY: SELECT FOR UPDATE on Wallet/Inventory before any mutation.
     Never trust a stale read — pessimistic locking is mandatory.
  2. REPLAY PROTECTION: Every on-chain tx hash -&gt; ProcessedTransaction (UNIQUE).
     Insert BEFORE crediting. If insert fails, tx was already processed — skip.
  3. RANDOMNESS: random.SystemRandom() ONLY. Never random.random()/choice().
  4. LEDGER: Every balance change MUST write a TransactionLedger row. No exceptions.
  5. BLOCKCHAIN_MODE: Check settings.BLOCKCHAIN_MODE before choosing RPC/addresses.
  6. CONTRACT ADDRESSES: Always from env (NEXT_PUBLIC_*) or settings. Never hardcode.
  7. PRIVY AUTH: Check authenticated before any wallet/backend mutation.
  8. NEVER PUSH TO MAIN/MASTER. Work on feature branches -&gt; merge to dev.
  9. CONVENTIONAL COMMITS: feat(scope): desc | fix(scope): desc | docs: | refactor:
 10. IDEMPOTENT MIGRATIONS: DB has renamed columns. Use DO $$ blocks in Alembic.

## 9. COMMON PATTERNS (code conventions)

  Backend endpoint pattern:
    router = APIRouter()
    @router.post('/path')
    async def endpoint(payload: Schema, user=Depends(get_current_user)):
    -&gt; validate -&gt; service call -&gt; commit -&gt; return response

  Frontend component pattern:
    'use client'
    export default function Component() {
    -&gt; hooks (useState, usePrivy, custom hooks)
    -&gt; handlers (async with try/catch)
    -&gt; JSX with Tailwind classes
    }

  Service layer pattern:
    async def service_operation(db: AsyncSession, user_id: UUID, ...):
    -&gt; SELECT FOR UPDATE where needed
    -&gt; business logic
    -&gt; db.add(ledger_entry)
    -&gt; await db.commit()
